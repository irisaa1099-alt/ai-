# 排查报告：改了人物设定，角色的说话方式却没变

- 排查时间：2026-09-21
- 排查对象：角色「牢大」（`c_499c1526c9ec`），现版本 v5
- 结论一句话：**改动确实生效了，提示词里就是新设定；说话方式没变是因为"人设卡里有另一个字段在教它说旧话"，外加历史消息与示例对话在拉着它。**

---

## 一、先回答那个最要紧的问题：修改生效了吗？

**生效了。** 用持久化的数据把那一轮的请求原样重建了一遍，`【关系】` 那一行是：

```
【关系】你与对方的关系是：你的私人训练伙伴和精神导师……；你称呼对方为「叫你「孩子」；等你真练出东西来了，才会直呼你的名字」
```

新版设定（「孩子」）**清清楚楚地在这轮提示词里**。

代码链路上也逐段确认过，没有任何缓存会挡住改动：

| 环节 | 位置 | 是否有缓存 |
| --- | --- | --- |
| 编辑器保存 | `ui/editor.js` saveDraft → `core/store.js` saveCharacter | 无；输入框 `input` 事件实时写进草稿 |
| 角色卡规范化 | `core/store.js` normalizeCharacter | 无；`persona` 是整体展开保留，不会丢字段 |
| 保存后刷新 | `core/store.js` emit `char:changed` → `ui/app.js` reloadCharacters | 无；当前页每次生成都取最新角色对象 |
| 装配提示词 | `core/prompt.js` buildSystemPrompt | 无缓存，每轮现拼 |
| 服务端代理 | `server.mjs` `/api/llm` | 不改写 messages，只透传 |

版本历史也能对上：`你称呼用户的方式` 字段在 **09-20 12:12 那次保存**就已经从 `叫你「kid」或「man」…` 改成了 `叫你「孩子」…`（v4），之后 v5 只是空存了一次（内容与 v4 完全一致，只动了 `updatedAt`）。

也就是说：**卡是新的，发给模型的是新的，是模型没照新的说。**

## 二、为什么模型没照新的说：四个叠在一起的原因

### 原因 1（主因，证据最硬）：同一个字段组里还有一句在教它说「kid」

`persona.particles`（编辑器里的「语气助词」）从来没有跟着改，它现在仍然是：

```
【说话方式】口头禅：「「Job's not finished.」……」；常用语气助词：几乎不用「呀、啦、呢」这类语气词；爱说「听着」「兄弟」「kid」；……
```

而 `addressUser` 那一句只说了「称呼对方为『孩子』」。
**同一行里，一边说"爱说 kid"，一边说"叫孩子"，模型选了"爱说"的那条。**

看 00:35:56 那条回复就明白了：

> 「听着，**kid**。别人练完回家睡觉的时候，我在练。……」

「听着」+「kid」正好就是 `persona.particles`（爱说「听着」「兄弟」「kid」）的原样组合，而不是 `addressUser` 的产物。
**这句 kid 是从「语气助词」字段里长出来的，不是从「称呼用户的方式」里长出来的。**

### 原因 2：`addressUser` 被模板包成了嵌套引号，读起来不像规则，像一个例子

`core/prompt.js:53`：

```js
rel.push(`你称呼对方为「${p.addressUser || user.name || '你'}」`);
```

它把字段值当成一个**短称呼**（编辑器里的占位符就是「你 / 老板 / 学姐」）。但内置的 39 个模板里，`addressUser` 的取值**全部是整句规则**，最短的一条也有 30 个字符（`叫你名字，或「你」`）。例如：

- `叫你「孩子」，熟了就加小名或「那谁家的」`
- `叫你「同学」或直接叫名字，心情好时给你取乱七八糟的绰号，比如「我的首席问题儿童」`

套进模板后就变成了「你称呼对方为『叫你「孩子」；等你真练出东西来了，才会直呼你的名字』」——
三层引号套在一起，`孩子` 这个词被降级成了**引文里的一个例子**，而不是一条指令。

更麻烦的是这句话的后半截「**等你真练出东西来了**，才会直呼你的名字」——它给了模型一个「现在还不必叫」的正当理由。模型的回复正好用了这个理由：

> 「看情况。你还没练出东西，就是 kid。练出来了，我才叫你名字。」

这是**执行了字段的后半句、忽略了字段的前半句**的典型表现。

### 原因 3：历史消息与示例对话在拉着旧语气

发给模型的消息里，除了 system，还有 **8 段"角色自己说过的话"**（2 段示例对话 + 6 条历史 assistant 消息），全是「」引号体、短句、带 kid。
在上下文里，"我自己前面是怎么说话的"这种**示范**，对措辞的影响远大于 system 里的一行文字描述。改人设不会改写已经落库的历史消息。

### 原因 4（对"说话风格"类改动最致命）：同一套风格在三个地方重复，而且最权威的那处在最后

这张卡里"说话风格"被写了**三遍**：

1. `persona.style`（说话风格）
2. `persona.speech`（编辑器标签叫「说话禁忌」，`buildSystemPrompt` 把它渲染成「语言习惯」）
3. `char.systemPrompt`（高级提示词里的「角色专属设定」），**渲染时排在最后，并明确写着「优先级高于以上通用准则」**

只改第 1 处，另外两处（尤其是优先级最高的第 3 处）还在讲老风格 —— 改动会被稀释掉。
`persona.speech` 那个字段的**界面标签（「说话禁忌」）和提示词语义（「语言习惯」）是反的**，用户很容易把"不要做的事"写进一个"要多做的事"的字段里。

## 三、附带的两个"看起来像没生效"的坑（本次不是主因，但值得记一笔）

1. **多标签页不同步角色卡。** `core/store.js` 只对 `settings` / `runtime` 挂了跨标签页监听（`bindStorageListener`，代码注释里就写着"改了没生效"这个症状），**角色卡没有**。如果你在另一个标签页/窗口里改人设，已经开着的聊天页内存里还是旧卡，不刷新页面就一直用旧的。这次的证据链显示是同一个页面，所以不是本次原因。
2. **Service Worker 是 stale-while-revalidate**（`sw.js`，缓存名 `aichat-v50`）。改了 `core/prompt.js` 之类的**代码**后，第一次刷新仍返回旧 JS，要**刷新两次**才是新代码。这只影响改代码，不影响改人设（角色卡走 IndexedDB / 数据接口）。

## 四、怎么验证 + 怎么改才有效

### 立刻可做的验证（30 秒，不花 API 钱）

打开「设置 → 上下文预算」预览，或直接看每轮请求 —— 只要 `【关系】` 那行是「孩子」，就说明**卡生效了，是模型没听**，接下来该改的是"教它的话"，而不是继续改这个字段。

### 让人设改动真正"说得出口"的四步

1. **改一个概念，要把相关的字段一起改。** 这次至少要把 `语气助词` 里的 `kid` 删掉，否则它永远压着 `称呼用户的方式`。
2. **`称呼用户的方式` 只写一个短称呼**（`孩子`、`老板`、`学姐`），把"什么时候才叫名字"这类条件规则挪到 `语言习惯` 或 `作者备注` 里。别在这个框里写整句。
3. **改说话风格，优先改两个地方**：`示例对话（few-shot）` 和 `角色专属设定（systemPrompt）`。前者是最强的示范，后者优先级最高。只改「说话风格」这个下拉框，几乎看不出变化。
4. **要验证风格是否真的换了，就做一个"干净"的测试**：清空该角色的聊天记录（或复制一个角色出来测），排除历史消息的惯性，再挑一个**不可能被忽略**的风格设定（比如"每句结尾加～"）来试。老会话里已经产生的语气，只能靠新消息慢慢覆盖。

### 可选：三处代码可以顺手修掉

| 位置 | 问题 | 建议 |
| --- | --- | --- |
| `core/prompt.js:53` | 把整句规则塞进「你称呼对方为「…」」的引号里，产生嵌套引号 + 语义降级 | 值短（无「」、无「；」、≤8 字）时按现在的写法；否则改渲染成独立一行 `称呼对方的方式：${value}` |
| `ui/editor.js:1582` | 标签「说话禁忌」写进 `persona.speech`，而提示词把它当「语言习惯」用 | 标签改成「语言习惯 / 说话方式」，避免把"不要做的事"写进"要多做的事"的字段 |
| `core/store.js:1163` | 角色卡不跨标签页同步，另一页改完不刷新就一直用旧卡 | 用 `BroadcastChannel` 广播 `char:changed`，或把角色卡也纳入 storage 监听 |
