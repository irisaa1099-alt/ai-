# 趣聊参赛版本复现说明

趣聊的核心体验是角色私聊、多人群聊与群内狼人杀：同一批角色能够跨场景持续互动。来源记忆让角色记住实际经历，并让用户查看来源、纠正错误。开放成果包括记忆记录与来源过滤、按听众筛选的近期经历、预算装配、合成场景和对照评测工具。没有训练基础模型，也不将模型供应商预设列表当作已使用的开源模型。

## 运行

本轮验证环境：macOS arm64、Node.js 24.19.0 / 24.20.0（具体运行见各协议）、本机 Chrome 无头浏览器。建议 Node.js 22 或更新版本，应用无 npm 运行依赖。其他系统尚未完成本轮实际验证。

安装 Ollama 后，在源码包的 app 目录执行 `node local-start.mjs --no-open`，打开 `http://127.0.0.1:5180`。文本模型固定为项目内 Qwen3 4B，无需商业 API Key。当前本机项目已包含权重；仅源码包首次启动时需要准备约 2.5GB 权重。旧用户配置自动迁移到本地模型。模型来源、许可与配置见 [本地模型说明](LOCAL-MODEL.md)。历史评测仍使用各实验记录中的原模型，不能作为本地 Qwen 成绩。此版本不提供商业模型或云语音入口，用户聊天不属于源码包。默认仅监听本机；局域网部署应按 server.mjs 的口令说明配置。

参赛副本保留林青、周予、许知、沈墨、程夏、唐野六名虚构模板，使用与原项目相同的核心模块。正式项目的人物模板和用户资料不会被发布构建覆盖。不要把运行后产生的 `data/db`、`.env`、备份或浏览器数据上传。

## 验证核心机制

1. 新建林青、周予，在林青私聊中给出明确的活动地点。
2. 到周予私聊询问同一地点，检查未公开事实不会被自动传入上下文。
3. 建立二人群，在群里明确公开地点，再回周予私聊询问。
4. 打开该角色的设置、上下文与记忆，重新整理记忆，查看事实来源。
5. 纠正一条地点记忆并等待关联核对，再询问；检查同义旧记录进入历史、开始时间等无关信息保留。需要可用模型连接，失败时原记录保留。
6. 同步并刷新，核对数据保留。

是否回答正确由实际模型决定；听众过滤证明输入边界，不保证模型不会猜中。角色知道一件事与用户允许角色公开是不同概念，本项目未实现完整的逐事实公开授权。

## 工程检查与真实模型评测

```sh
node tools/contestcheck.mjs
node tools/securitycheck.mjs
node tools/memorycheck.mjs
node tools/groupbudgetcheck.mjs
node tools/optimizationcheck.mjs
node tools/providercheck.mjs

```

检查使用临时数据和独立浏览器；`--live` 会调用已配置的真实服务。完整真实轮次包含40个合成实例、六组对照，通常282次请求。详情见 tools/memory-eval/README.md。工程检查通过数、模拟模型输出与真实模型评分分别报告。评分代码和固定场景保持 memory-eval-v1，不为新结果放宽未知答案格式。

旧v1历史证据使用 `contest-20261025/live-final` 完整轮次；前一轮 `live` 因修正分项计量并冻结代码而主动停止，保留为中断记录，不混入正式统计。每格只回答一次，没有挑最好结果；模型版本可漂移，不能保证复跑逐字一致。

## 复用核心代码

`core/memory.js` 的 `makeMemorySource`、`normalizeMemory`、`correctFact`、`retractFact` 和 `filterMemoryContext` 可以在自己的数据适配层中使用：给事实记录绑定原消息ID、会话及内容签名；纠正时保留旧记录并建立替换关系；读取来源时重新验证归属、听众和签名；最后过滤当前历史、近期片段与引用快照。

`core/recent.js` 定义近期经历的筛选与格式；`core/prompt.js` 和 `core/group.js` 负责装配。若复用到其他应用，需要自己实现存储、时间与用户身份适配，不能仅复制提示词而省略来源校验。`tools/memory-eval/scenarios.mjs` 是可读的固定场景和评分器；六组定义与输入快照便于其他项目实现同协议对照。

## 版本与问题反馈

以包内 RELEASE_MANIFEST.json 的源文件 SHA-256 为准；Git 基线、改动文件和替换的模板均明确列出。仓库主分支可能继续变化，复现时应使用随包源码。反馈时附版本摘要、操作步骤、预期与实际结果、浏览器及模型名称，只附合成例子，不附密钥或私人聊天。维护顺序是确认可复现问题、增加针对性检查、修复、更新版本与验证记录。

## 已知限制

未开展用户试用、角色一致性盲评、公网部署压力测试或跨平台验收。40例来自五类受控模板，不是40种独立真实任务。严格匹配会把含额外解释的未知回答判为失败；任何语义复核均须单列且注明审核者。预算基于估算器，不是供应商 tokenizer；极低预算或超大事实仍可能丢内容，明细只计实际保留文本。没有来源的旧事实和语义改写不受内容签名完全覆盖。


## 聊天、群聊与游戏（r2补强）

产品的主要入口是角色私聊、多人群聊和群内狼人杀。来源记忆支持这些持续互动，不能用记忆问答成绩代表所有聊天体验或游戏水平。

先添加至少5位中性角色，再新建包含他们的群。普通群聊可点名某人或让成员轮流接话；群资料中打开狼人杀，选择快速或标准模式。5位角色加用户构成6人局（2狼、2民、预言家、女巫，女巫仅解药）。用户在操作条行动，自己的发言通过聊天输入框提交。结算后退出游戏模式，回私聊可谈及明确标注的游戏经历。

新增修复：未知事实不应由角色语气补造成“我确认过”；允许准确转述已公开的他人发言；提取保留发言者归属。同群同日不同对局分别保存经历，同一局重复结算保持幂等，不恢复已撤回记录。

```sh
node tools/groupcheck.mjs
node tools/werewolfcheck.mjs
node tools/game-sessioncheck.mjs
node examples/memory-flow.mjs
```

新场景、合理角色摘要基线及全组语义复核见 tools/core-eval/README.md。最终证据使用 r2/final-live；r2/live、r2/live-final与r2/v21-live-final为开发轮，含已发现的评测夹具问题，旧v1轮原分不变。所有语义复核均为AI辅助，包含裁判误判更正记录，不声称独立人工评审。
