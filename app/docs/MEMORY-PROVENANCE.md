# 长期记忆：来源、纠正与兼容边界

本文对应 2026-10-22 的实现。近期原始消息的跨场景使用见 [近期经历说明](RECENT-EXPERIENCES.md)，本轮修改及验证结果见 [修改记录](BUGFIX-2026-10-22.md)。

## 使用方式

先在左侧打开一位好友的私聊，再进入「设置 → 记忆与上下文」，即可查看该角色的有效事实、来源、滚动摘要，以及可展开的历史记录。

- **查看来源**：弹窗显示角色可查看的当前消息内容、时间和私聊/群聊场景。原消息已删除或不再满足可见条件时，不显示旧内容或缓存摘录；内容发生变化时显示当前内容并标明变化。
- **纠正**：输入 1 至 500 字的正确内容。原条目进入「已修正」历史，新条目标记为人工纠正，并保存替换关系。有效事实和来源变化的事实可纠正。
- **撤回**：确认后停止使用该有效事实，保留「已撤回」历史。其他已失效条目保留查看能力。
- **重新整理记忆**：从该角色现存的私聊和有听众依据的群消息重新提取；旧模型事实不再无条件拼回，人工纠正、有效游戏结算记忆及纠正/撤回历史保留。被阻断的原来源会从提取输入排除。整理失败或与新修改冲突时会提示，保留原存档。
- **清空记忆**：清除摘要、事实及纠正/撤回历史。聊天原文不删除；失去撤回历史后，原文可能在后续整理中再次被提取。

上述操作不修改原消息。若聊天原文也有错误，需要另外编辑或删除原消息；纠正/撤回长期记忆不会将该消息从普通聊天历史和近期经历中删除。

## 记录结构与来源含义

`core/memory.js` 定义兼容结构和纯函数，`core/store.js` 负责持久化及来源可见性。记录仍存于原有 memory 表及对应文件，不新增数据库表。

| 字段 | 含义 |
|---|---|
| `factRecords[].id` / `text` | 事实标识和文本；新记录使用独立标识，旧字符串事实生成稳定的兼容标识 |
| `status` | `active` 有效；`superseded` 已被替代；`retracted` 已撤回；`stale` 来源已改变或不可用 |
| `origin` | `model` 模型提取；`manual` 人工记录/纠正；`legacy` 旧格式兼容；`game` 确定性游戏结算 |
| `sources[]` | 来源的 `kind`、`conversationId`、`messageId`、`at`、`speakerId`、`signature` |
| `sourceStatus` | `verified` 表示关联到本轮核对过的来源；`unverified` 表示没有可核验关联 |
| `createdAt` / `updatedAt` | 条目建立/更新时刻 |
| `replaces` / `blocked` | 新人工事实替代的旧事实标识；旧条目阻止相同来源或文本重新进入提取结果 |
| `summary` / `summarySources` / `summaryStatus` | 摘要、摘要依赖的来源，以及有效、未核验或停用状态 |
| `summaryCursors` / `summarizedUpTo` | 各私聊/群聊的摘要进度，以及旧私聊进度兼容字段 |
| `revision` / `schemaVersion` | 记忆保存修订号及结构版本；当前结构版本为 2 |

来源键由类型、会话 ID 和消息 ID 组成。`signature` 根据当前有效消息内容的长度与两次轻量哈希生成，用于发现消息变化，不是密码学认证，也不证明消息作者身份或内容真实。多版本回复以当前选中的版本为准。

新提取请求给模型提供本批消息 ID，要求输出 `{text, sourceIds}`。返回的来源 ID 必须存在于本轮已检查的来源映射中；一条事实含未知 ID 时整条拒绝，同次生成的摘要也停用，避免事实被拒绝后仍从摘要进入提示词。旧模型返回的纯字符串仍可兼容，但标记为未核验，不能补造来源。

狼人杀结算通过 `appendGameMemoryFact` 原子追加 `origin: game` 的事实，保留已有结构与纠错历史；不把局内隐私信息伪装成普通聊天来源。游戏条目没有聊天来源关联，标为 `unverified`，有效条目在重建时保留。

**`verified` 只证明来源关联通过程序检查，不证明来源支持该事实的语义，也不证明原发言是真实陈述。** 模型仍可能误读、过度推断或将玩笑当成事实；提示词约束和来源校验不能代替真实模型评测。

## 读取过滤与提示词选择

`getMemory(charId)` 读取后逐项核对来源：私聊必须属于该角色，群聊必须满足原有的实际听众判断。任何关联来源不可用或内容签名改变，该条事实在本次读取结果中标为 `stale`，不再进入有效事实列表；摘要依赖的任一来源失效，也会停用该摘要。

这属于读取时过滤，不会因为打开设置或聊天就写回整个旧记忆。历史无来源记录无法做这种变化检测，仍可兼容使用，界面明确显示「历史记忆，来源未记录」。

提示词只选择有效事实，默认最多 40 条。选择按当前查询的简单词项匹配排序，同等相关时优先较新的事实；不是向量检索或语义检索。私聊、群聊均使用该选择函数，再受各自总上下文预算限制，不保证每一条事实在每轮都送入模型。历史记录保留在存储中，40 条仅是本轮提示词选择上限。

纠正或撤回后，原摘要可能仍含旧错误，因此标为 `stale` 并暂不送入模型。当前实现只要仍保留阻断记录，后续摘要合并也继续保守停用摘要；重新整理不保证自动恢复摘要使用。有效人工事实仍参与选择。

## 纠正、重建与并发保存

纠正和撤回在同一个 IndexedDB 读写事务中读取最新记录并保存状态，修订号递增。旧事实不会物理删除，新人工纠正记录没有伪造的聊天来源。

自动摘要按角色串行执行，私聊和各群聊分别记录进度。手动重建读取该角色可用的完整历史，在内存中分批提取；各批次完成后才提交一次记忆。任何模型调用失败、结果无法解析或最终保存冲突，均不先清空旧存档，也不保存部分批次的半成品。全部消息都已被阻断或没有可处理消息时，可以保持原记忆不变。

自动摘要和重建保存时携带开始时的 `expectedRevision`。如果等待模型期间当前 IndexedDB 的记忆已被人工纠正、撤回或其他保存更新，修订号不匹配会拒绝覆盖并保留最新记忆。这是当前数据库内的并发保护，不等于跨设备分布式事务或模型服务端回滚。提交成功后沿用原有磁盘镜像与同步流程。

被纠正或撤回的条目保留阻断信息：相同来源键与相同内容签名的消息不再作为提取输入，相同旧事实文本不会重新加入。**没有来源的历史事实只能阻断相同文本，不能识别和保证阻断所有语义改写。** 即使有来源关联，模型从其他材料产生相近错误也仍需人工核对。

## 旧数据、备份与恢复

- 旧 `summary` / `facts` 结构由 `normalizeMemory` 在内存中转换，保留原摘要与事实；不自动推测其来源，不自动重算，也不在读取时持久化迁移。
- `facts` 继续作为有效条目文本的兼容视图；显式保存 `factRecords: []` 才表示清空结构化记录，避免从旧字段意外恢复。
- 正常备份保留事实状态、来源、阻断记录及摘要进度。合并导入在角色、群及消息的新 ID 确定后，重映射事实来源、摘要来源和进度中的消息 ID，避免仍引用原角色的消息。
- 缺失或不可见的导入来源不会被补造；下次读取按可用性过滤。旧备份没有来源时继续显示未记录。
- 群消息继续使用 `audienceIds` / `memberSince` 及旧数据兼容规则；来源追溯没有放宽角色间的信息边界。

## 验证与未覆盖范围

`node tools/memorycheck.mjs` 使用合成消息、临时源码和数据库、独立浏览器及本地假模型，覆盖来源归因、编辑/删除失效、纠正/撤回、旧数据只读兼容、迟到保存冲突、重建及备份恢复。`node tools/groupbudgetcheck.mjs` 使用合成输入检查群聊估算预算和必要片段保留。
