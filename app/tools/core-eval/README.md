# 核心体验新场景评测（core-eval-v3.2）

目的：验证私聊和群聊中的多事实、连续改口、暂定状态、否定偏好、人物归属、猜测、纠正、撤回、游戏与日常分离、多人分工、新成员和私聊边界等。31个固定场景，三组，每组各重复两次，共186条回答。模型、预算及可见证据保持一致；不以假模型输出证明效果。

在 app 下运行：

```sh
node tools/core-eval.mjs --dry-run --full --repeats 1 --out /新的目录/pipeline
node tools/core-eval/check-run.mjs /新的目录/pipeline
node tools/core-eval.mjs --live --full --from-site --repeats 2 --max-calls 420 --out /新的目录/live
node tools/core-eval/check-run.mjs /新的目录/live
node tools/core-eval/semantic-review.mjs /旧v1完整轮次 /新的目录/live /新的目录/review
# 只评新数据集：旧v1路径传 -
```

需要 Node.js 22+、Chrome/Chromium及已有模型连接配置。真实模式会收费；上限按请求数限制，不是金额。只从正式设置取连接信息，聊天数据不进入用例，正式数据库前后校验。假模型只验证装配管线，不预设正确答案。

三组定义：
- no_memory：当前会话窗口，不加长期记忆或跨会话经历。
- role_summary：独立为每位角色生成摘要。输入遵守相同听众范围，并包含同样的编辑、更正、撤回通知；每场景每次重复独立生成，不使用正确答案编摘要。复用产品装配器、同一人设、当前窗口和4000 token估算预算，关闭近期经历。不是对外部产品的实测。
- current：产品实际记忆提取、来源验证、纠正、近期经历和装配。

提取及摘要温度0.3、输出1100 token、非思考，回答温度0、输出256 token、非思考。对照组顺序轮换。提取失败不补标准答案。两次重复用于观察波动，不足以估计稳定显著性。当前组与摘要组的预处理成本均应单列，不将总调用重复相加。

语义复核保存独立协议、匿名输入、映射、原始裁判响应和每格理由。裁判看不到组名和原始分数；同一规则覆盖全部组，分别检查事实、听众边界、无依据推断和格式。综合语义通过不包含格式分。裁判也是AI，且可能与被测模型属于同一家族；不是独立人工盲评。严格词面原分数保持不变。错误/缺行/截断会中止，不悄悄重试挑答案。

v2开发轮发现问题后用于一次通用规则修订。随后修正评测夹具中的用户speakerName、接人陈述方向与一条开放式提问，升级为v2.1；R2正式结果来自final-live；R3正式结果使用final-v32。此前live/live-final/v21-live-final均作为开发记录保留，不能跨协议直接计算提升。v2.1也不是未见测试集。原v1六组的语义复核针对原始240条历史回答，并非新版本重跑。

游戏另用真实应用完整局和工程用例验证：node tools/werewolfcheck.mjs、node tools/game-sessioncheck.mjs。聊天问答分数不代表狼人杀策略强度或娱乐性。

R3增加13例改期/纠正专项；纠正场景只操作一次，调用实际同义关联服务，包含额外真实调用。旧版混合条目用明确标注的来源夹具验证迁移，其余使用模型提取。所有回答前重新加载页面，再从IndexedDB读取记忆；每个场景、组别、重复均保留。增量提取按时间顺序分批执行，人工更正后同义事实与未改变的独立信息同时核对。

原始词面评分会将否定旧时间也标为失败，保留原规则并通过独立列出的AI语义复核解释，不按看到的答案修改评分器。AI裁判不是独立人工审核。

最终v3.2在同义纠正与旧版混合条目用例中，纠正后还调用真实重新整理，再刷新回答；R3早期release-live是重整保留修订前的开发完整轮，保留而不拼入正式统计。

最终语义审核的第36批有一个无格式要求条目漏填formatPass。使用recover-review.mjs显式恢复原始响应，将唯一漏填且无格式规则的字段记为null，保留中断协议与所有原判；随后只审核尚未请求的42条，没有重新抽取或挑选产品回答。恢复脚本拒绝其他错误与重复恢复。最终186条均有复核。
